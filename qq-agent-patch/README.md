# qq-agent 私聊「主动搭话」补丁

给 [qq-agent](https://github.com/lyyde599/qq-agent) 加一颗会自己起话头的心：**没人说话的时候，它也可能先开口。**

原作者其实已经写了主动开话题的循环，但它**只对群聊生效**，私聊永远轮不到。这个补丁干两件事：

1. 把私聊也加进候选（原版在两处把 `kind !== 'group'` 直接 `continue` 掉，其中一行还是重复的，等于私聊被筛两遍）；
2. 把原来「固定间隔 × 固定概率」的粗糙逻辑，换成一套**带时机判断**的掷骰：

```
每 30 分钟掷一次骰子（纯本地随机，不花 token）
  ├─ 安静时段（默认 1~8 点）→ 根本不掷
  ├─ 刚开口过（冷却 20 分钟）→ 不掷
  ├─ 会话没安静够（默认 45 分钟）→ 不掷
  └─ 掷：命中线 = 峰/谷时基准 × 时机因子 + 连续没中加成
        掷中才真开口，没中只记一笔
```

## 命中线怎么算

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 峰时命中线 | 20% | 周一~周五 09:00–12:00、14:00–18:00 |
| 谷时命中线 | 60% | 其余全部（含午休、夜里、周末） |
| 时机因子 | 0.15 / 1 / 1.5 | 距上次说话 <20 分钟 → ×0.15；>6 小时 → ×1.5；中间 ×1 |
| 没中加成 | +10 | 每连续没中一次，命中线加 10 |
| 加成上限 | +40 | 最多加到 40 |
| 冷却 | 20 分钟 | 它刚自己开过口，这段时间内不再开口 |
| 安静时段 | 1~8 | 含起不含止，跨午夜也支持；`起 === 止` = 不启用 |
| 间隔 | 30 分钟 | 两次掷骰之间隔多久 |
| 闲置门槛 | 45 分钟 | 会话要安静这么久才进入候选 |
| 试运行 | 关 | 开着时掷中也不真发，只写日志 |

命中线 = `min(100, 基准 × 时机因子 + min(加成上限, 连续没中次数 × 没中加成))`，掷出小于命中线就开口。

**所有判定都写进 `data/proactive-log.txt`**，比如：

```
2026/10/24 21:06:06  没中：掷出 28.4 ／ 命中线 19.0（谷时／刚聊过×0.15／没中加成+10，连没中 2 次）
2026/10/24 21:20:11  命中并开口：掷出 12.1 ／ 命中线 60.0（谷时／×1，已安静 51 分钟）
```

## 装

需要 Node ≥ 20，qq-agent 已经能正常跑。

```bash
# 在 qq-agent 目录里执行（会把补丁打进 src/orchestrator.js）
node install.mjs

# 也可以指定 qq-agent 的位置
node install.mjs D:\bots\qq-agent
```

脚本会：

1. 检查 `src/orchestrator.js` 存在、且**没有**打过这个补丁（打过就跳过）；
2. 备份成 `src/orchestrator.js.bak-proactive`；
3. 用括号配对找到 `startProactiveLoop()` 这一个方法的完整范围，整段替换（**只动这个方法，不碰其它代码**）；
4. 如果 `data/config.json` 存在，往 `proactive` 段里补上新参数（保留你已有的值）。

然后：

```bash
# 重启 qq-agent（按你的方式，比如）
systemctl restart qq-agent
# 或者 npm run server
```

## 先试运行，别直接开

1. 把 `data/config.json` 里 `proactive.dryRun` 设成 `true`；
2. 把 `intervalMinMs` 临时改小（比如 `60000`），跑两轮看 `data/proactive-log.txt`；
3. 看命中线的数字是不是你想要的节奏，不合适就调 `peakPct` / `offPeakPct`；
4. 满意了再关掉 `dryRun`，`intervalMinMs` 调回 `1800000`。

## 注意事项

- **升级 qq-agent 会覆盖这个补丁**（`npm update`、重新 clone、换版本），升级完重新跑一次 `install.mjs` 就行。备份文件 `orchestrator.js.bak-proactive` 留着，想回退直接改名覆盖回去。
- 补丁只替换 `startProactiveLoop()` 一个方法，原来那个 `#proactiveCandidates()` 会变成没人调用的死代码，留着不影响运行。
- 判定状态存在 `data/proactive-state.json`（连续没中次数、上次开口时间），日志在 `data/proactive-log.txt`（只留最近 200 行）。
- 私聊要不要开口，仍然受 `allow.private` 白名单约束——名单里的才会被唤醒。
- 这个补丁**不解决**「模型会不会说人话」的问题。它只决定**什么时候**叫它开口，说什么还是人设的事。想让它别一开口就是「好久没聊了」，去人设/规则里写死。
